## 2. 现状勘察结论（已核实，含出处）

### 2.1 播放链路是单播放器 + 会话代理

- `service/RadioService.kt`（330 行）是 `MediaSessionService`，`initializePlayer()` 在 `onCreate` 里建**唯一一个** `ExoPlayer`（约 L108-153），包一层 `SkipTogglePlayer`（`ForwardingPlayer`，L293-308）后交给 `MediaSession`。
- `service/PlayerManager.kt`（723 行）是 `@Singleton`，通过 `MediaController` 连到那个会话（L172-191 `connect()`），电台与戏曲**共用**这一路：`playStation`(L269) 先 `stopOpera()`；`playOperaFile`(L475) 先 `_currentStation.value = null`。**互斥已经存在**，D2 的语义天然成立，不需要新造。
- 播放模式判定靠 `_isOperaMode: StateFlow<Boolean>`（L142-143）；倍速/循环/断点续播都挂在 `PlayerManager` 上，页面直读，不经 ViewModel（见记忆「播放状态与TTS引擎处理规范」「播放链路两条结构约束」）。

### 2.2 决定性技术事实

- **`RadioService` 没有 `android:process`**（`AndroidManifest.xml` L47-54）→ 与 `MainActivity` **同进程** → UI 侧可以直接拿到那个 `ExoPlayer` 对象绑画面。这是方案①成立的前提。
- **`MediaController` 不能绑视频输出面**：Media3 的 `setVideoSurface/setVideoSurfaceHolder/setVideoSurfaceView` 在 controller 上抛 `UnsupportedOperationException`，画面必须绑在播放器所在进程的那个对象上。→ 所以必须要注册表，不能图省事直接用 `PlayerManager` 那个 controller。
- 依赖已齐，**不需要新增任何库**：`gradle/libs.versions.toml` 已有 `media3 = "1.5.1"` 的 `media3-exoplayer` / `media3-exoplayer-hls` / `media3-session` / **`media3-ui`**（`PlayerView` 在里）。`DefaultMediaSourceFactory` 会自动识别 m3u8。
- `MainActivity` **没有 `android:configChanges`**（Manifest L35-44）→ 旋转会重建 Activity → 画面组件需靠 `DisposableEffect` 重新挂载；播放器在服务里不受影响，音频今天已经能扛住旋转。
- 权限现状：只有 `READ_MEDIA_AUDIO` + `READ_EXTERNAL_STORAGE(maxSdk 32)`（Manifest L12-13）。**C 期需要另加 `READ_MEDIA_VIDEO`**，本轮 spec 不碰。

### 2.3 「电视伴音」里其实藏着真视频流（本轮最重要的发现）

`app/src/main/assets/radio_stations.json`（404 KB）分类实测分布：

```
world 257 · music 129 · news 86 · tv_audio 62 · general 56
traffic 56 · finance 29 · arts 28 · opera 9 · sports 8
全库含 m3u8 的台：382
```

`tv_audio` 有 **62 个台**，且**两种性质完全不同**混在一起：

| 类型 | 样本 id / 台名 | 流地址 | 实际内容 |
|---|---|---|---|
| 卫视频道 | `tv_bj` 北京卫视、`tv_nx` 宁夏卫视 | `https://satellitepull.cnr.cn/live/wxbtv/playlist.m3u8` | **本来就有画面**，现在只因没绑面而只出声 |
| 纯伴音 | `st_CCTV-5体育伴音`、`st_CCTV-5+体育赛事伴音` | `https://piccpndali.v.myalicdn.com/audio/cctv5_2.m3u8` | 只有音频轨，永远出不了画面 |

→ A 期不需要为新视频源做数据接入，但**必须能区分这两类**。结论见 §4「不预先标数据，靠运行时真相」。

### 2.4 云盘视频文件其实已经在列表里了

`domain/PlayableTrack.kt` 用的是**黑名单**（只排除 `lrc/jpg/png/txt/srt/ass/vtt/nfo/json/xml` 等附属文件），注释写明理由：白名单会误杀 wav/flac/m3u8。所以 **mp4/mkv 现在就已经出现在音频库列表里**，点一下会走 `playOperaFile` 放出声音 —— B 期缺的只是画面，不是接入。这条对 B 期的工作量判断很关键。

相关模型：`domain/model/YunPanOperaModels.kt` 的 `OperaAudioFile(fileId, name, size, categoryName, operaName, downloadUrl, etag, s3KeyFlag, sourcePath)` —— **没有任何类型/媒体种类字段**。`data/local/AudioSourceEntity.kt`、`domain/AudioModels.kt` 同样没有。

### 2.5 UI 落点的现有骨架

- 底部三 Tab：`ui/MainScreen.kt` L143-150（电台 / 音频库 / 设置）。`Screen.kt` 现有路由：radio, audio, player/{stationId}, opera_player, epg, settings, manage, tags, diagnostics, key_settings。**本轮不新增路由**。
- `ui/player/OperaPlayerScreen.kt`（491 行）主体是 `Column { info(); contentArea(Modifier.weight(1f)); slider(); controls() }`（L147-152），`contentArea` 是「封面+歌词两页可滑」的四态矩阵（L233+）。→ 画面区应接在 `contentArea` 的位置，歌词退居可切换页签。
- `ui/player/PlayerScreen.kt`（692 行）已经是**可滚动 Column**（L157+，注释写明此前不可滚动导致大字号/横屏把播放键顶出屏幕）；车机档把封面与台名做成 `Row` 左右并排（L167-182），封面在 `Box(Modifier.weight(1f))` 里。→ 画面区替换 `CoverBlock` 的位置最自然。
- 形态：`ui/theme/Dimens.kt` + `isCarSurface()`（两页都在用，如 OperaPlayerScreen L73/L76）；车机档硬约束是 `Dimens.TouchMin` 命中区。

## 3. 已呈现但**未获批准**的设计 §1（视频内核）与 §2（画面判定）

下面这版是 23:5x 时发给用户等批准的原文要点。**状态：待批准。**

### §1 视频内核（四件事）

1. **播放器实例注册表** `service/VideoPlayerMount.kt`（`@Singleton`）
   - `RadioService.initializePlayer()` 建好 `ExoPlayer` 后写入；`onDestroy` 清空。
   - `PlayerManager` 继续用 `MediaController` 做**全部**播控，现有播控逻辑一行不改。
2. **视频轨闸门（核心防线）**
   - `ExoPlayer` 建好后立即 `setTrackSelectionParameters { setTrackTypeDisabled(C.TRACK_TYPE_VIDEO, true) }`。
   - 默认**根本不解码视频** → 今天所有「只听声」的行为、起播耗时、耗电与改造前完全一致。
   - 画面挂上才解禁，画面摘掉立刻重新禁用。
   - 注意：`ExoPlayer.setTrackSelectionParameters` 必须在其 application looper（此处即主线程）调用；`PlayerManager.scope` 是 `Dispatchers.Main`，Compose 也在主线程，成立但需写成断言。
3. **画面组件** `ui/common/VideoStage.kt`
   - `AndroidView { PlayerView }`，`useController=false`、`RESIZE_MODE_FIT`（自带黑边适配，不拉伸）。
   - 绑**注册表里的 `ExoPlayer`**，绝不绑 `MediaController`（会抛 `UnsupportedOperationException`）。
   - 挂载 → 解禁视频轨 + `playerView.setPlayer(exo)`；卸载 → `setPlayer(null)` + 重新禁用。
   - 播放中给窗口加 `FLAG_KEEP_SCREEN_ON`。
   - 转场交叉淡入时可能两三个 Stage 短暂共存：用「单一 mountedView，后来者顶掉前者，且只在前者仍是自己时才摘」的规则，不做引用计数。
4. **单一状态源**：`PlayerManager` 只新增两样
   - `hasVideoTrack: StateFlow<Boolean>` ← `onTracksChanged` 里存在 `C.TRACK_TYPE_VIDEO`
   - `mountVideoStage() / demountVideoStage()`
   - 页面一律读它，**不许自己判 URL**。

### §2 「能不能出画面」的判定规则

一律以运行时真相为准，不改数据文件：

| 场景 | 判定方式 | 结果 |
|---|---|---|
| 云盘 mp4/mkv/mov/ts/flv/webm | `PlayableTrack` 黑名单不动；新增正向纯函数 `VideoMedia.looksLikeVideo(name)`，**只用于列表徽标** | 点进去照旧走 `playOperaFile`，有视频轨则播放页长画面 |
| 北京卫视等 `satellitepull.cnr.cn/...playlist.m3u8` | 起播后 `currentTracks` 出现视频轨 | 自动出画面 |
| `cctv5_2.m3u8` 这类纯伴音 | 永远不会有视频轨 | **页面与今天逐像素一致，一行不改** |

已如实告知用户的代价：**直播流在进去之前无法显示「有画面」徽标**（云盘文件能标，直播流标不了）。换来的是 A 期 62 个台**不用手工标注、不用改 `radio_stations.json`、不用动 Room 表**。

## 4. 明天要接着问 / 要定的事（按优先级）

1. **先补 §1/§2 的批准**（含 §2 那个取舍是否接受）。若拒绝取舍，备选是：给 `RadioStation` 加 `hasVideo` 字段并手工标注 62 个台 + 写一次性 Python 探测脚本批量验证（符合本项目「Python 先行验证再同步 Kotlin」规范）。
2. **§3 A 期的换源语义**（我这边已有建议，待拍）：电台多源轮转（`SourceRotationEngine` + `playQueueSource`）从「有画面的卫视流」换到「无画面的镜像伴音流」时，画面区**保持占位并显示「该节目源无画面，正在听声」**，不 collapse，避免整页布局抖动。
3. **§4 B 期的画面与歌词共存**：有视频时画面占 `contentArea` 全部，歌词收进可切换页签还是点击画面浮出？（涉及「播放页控件必须保持单行不可拆多行」这条既有红线）
4. **§5 两形态布局红线**：车机 1280x720 恒横屏加了画面后，**播控行必须仍在首屏内**。已知坑（记忆）：整块可点卡片逐行撑 `TouchMin` 会把播控顶出车机首屏。手机档渲染结果须与改造前逐像素一致作为回归基线。
5. **§6 测试与验收**：
   - 纯函数单测（JUnit/MockK）：`VideoMedia.looksLikeVideo`、`hasVideoTrack` 判定、**默认视频轨为禁用态**的回归守卫（防止哪天改成默认开导致全局多解码）。
   - 不许动 `BrowserFactoryTest` 里 `assertSame(shared, factory.browseClient(src))` 那条 WebDAV 凭证不变式。
   - uiautomator bounds：车机档播控行 `max(y) < 720`。
   - 截图判「真有画面」：取画面区中心**两帧差分**，不用单阈值（记忆教训：单阈值假失败）。
6. **spec 落盘位置**：本项目约定是 `doc/specs/YYYY-MM-DD-<topic>-design.md` + `doc/plans/`（**不是** skill 默认的 `docs/superpowers/specs/`）。建议文件名 `doc/specs/2026-11-02-video-playback-kernel-ab-design.md`。
7. D5/D6 已定，别再重开：不做画中画、不做行车遮罩、不新增 Tab、不新增依赖。
