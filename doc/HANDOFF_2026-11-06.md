## 3. 明日第一件事：修完 Task 1 审查的 3 个 Important

Task 1 已提交但**审查发现的 3 个 Important 一条都还没修**。按既定规矩（Critical/Important 当场修完才进下一任务），明天必须先做这一节，**不要跳过直接开 Task 2**。

### I-1 · 计划文档没跟上"统一形状"这个改动（阻塞 Task 2）

执行时把 iptv 清单统一到 `{"stations":[...]}` 包装 + `StationJson.parse`（因为 `radio_stations.json` 顶层就是包装对象，且 `StationJson` 是手写解析器），但**计划文档一个字没改**：

- Task 2 工具仍写 `ConvertTo-Json @($rec)`（裸数组）
- Task 2 的 `IptvAssetsGateTest` 与 Task 4 的 `all()` 仍写 `Json.decodeFromString<List<RadioStation>>`
- Task 4 测试样例也是裸数组

**后果**：照计划文本执行 Task 2，形状不匹配会被 `runCatching{}.getOrElse{ emptyList() }` 静默吞掉 → **iptv 页一条频道都没有**，只有一行 `Log.w`，而编译和单测全绿。

**修法**：改计划三处 —— 工具产出改 `ConvertTo-Json @{ stations = $rec } -Depth 6 -Compress`；Task 2 的 Produces 与闸门测试、Task 4 的 `all()` 与测试样例全部改成 `StationJson.parse(raw)`。

### I-2 · `adultCategoryKey` 与 `IptvCategory.ADULT` 的"同一个字"约束是空的

计划 Task 3 那条守卫测试写的是 `assertEquals("xxx", IptvCategory.ADULT.key)` —— **硬编码字面量，全文没引用 `IptvAdult`**。谁改了任一侧，测试照样绿。

**后果**：`isAdult` 的 `tags.contains("xxx")` 半边失效 → 只靠 `xxx` 分类标记、`is_nsfw=false` 的频道在**开关关着（默认）时直接出现在列表和搜索里**。V2 唯一的默认隐藏闸门无声失效。

**修法**（两行）：

```kotlin
ADULT(IptvAdult.adultCategoryKey, "成人");          // IptvCategory 里，让常量只有一个出处
assertEquals(IptvAdult.adultCategoryKey, IptvCategory.ADULT.key)   // 测试断言关系而非字面量
```

### I-3 · "老数据零迁移"守卫被改窄，DataStore 那条路径没测到

我把测试从 `kotlinx.decodeFromString` 换成 `StationJson.parse` 时，连**用户自建电台**那条也换了。但自建台走的是 `StationRepository.getCustomStations()` 的 `json.decodeFromString`（L141），是**另一条解析路径、另一套默认值机制**。现在测试名字说的场景与它实际测的东西不符。

**后果**：将来有人"整理模型"去掉默认值 → 升级后管理页自建台整批消失、收藏里那几条点不开；测试会红，但红在一条名字与场景不符的用例上，修复者容易改错地方。

**修法**：补回一条 kotlinx 路径的测试（不删现有断言）：

```kotlin
@Test
fun `DataStore 里的老自建台 JSON 必须解出默认值`() {
    val legacy = """[{"id":"custom_1","name":"我的台","category":"news","streamUrl":"https://a/b.mp3","sources":[]}]"""
    val st = kotlinx.serialization.json.Json { ignoreUnknownKeys = true }
        .decodeFromString<List<RadioStation>>(legacy).single()
    assertFalse(st.nsfw); assertTrue(st.altNames.isEmpty())
}
```

### Task 1 审查留下的 Minor（记下来，按规矩由用户决定是否修）

- **M-1**：`StationJson.string()` 对显式 JSON `null` 会返回字符串 `"null"`（`JsonNull.content` 的行为），于是 `userAgent: null` → `"null"` → 发出 `User-Agent: null` 被 CDN 403 拒。当前**不触发**（真实清单 0 个 `: null`，工具用 `[string]` 归一成空串），但 iptv-org 上游明确用 null 表达"无 UA"。修法一行：`string()` 里排除 `JsonNull`。
- **M-2**：`nsfw` 用 `toBooleanStrictOrNull() ?: false`，`"True"`/`"1"` 会静默判"非成人"（内容门 fail-open）。建议抽 `boolean(key)` 私有助手并让工具侧断言必须是布尔。
- **M-3**：`StreamHeaders("","")` 这个状态类型本身允许，不变量只在注释里。建议加 `companion fun of(...)` 两者皆空白返回 null。
- **M-4**：真实 assets 那条测试把「schema 默认值」与「电台清单不含成人」两件事混在一条断言里，红了没有归因；且三个新字段漏验 `referrer`。
- **M-5（计划层面）**：Task 6 的 header 查表按 `allSources().first()` 取，而 header 是**逐流**的 → 用户手动切到第 2 源会塞第 1 源的 header 导致 403。Task 6 执行时必须按"当前正在播的 url"查。
